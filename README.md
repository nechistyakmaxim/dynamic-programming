# Динамическое программирование. Просто о сложных решениях
«Оптимальность — это не поиск идеала, а умение не пересчитывать одно и то же дважды»
Представьте, что вы стоите перед огромной головоломкой. Вместо того чтобы пытаться собрать её целиком за один раз, вы замечаете, что одни и те же фрагменты повторяются снова и снова. Если бы вы могли запомнить, как вы уже собирали эти фрагменты, вы бы сэкономили кучу времени и усилий. Именно так работает **динамическое программирование** (Dynamic Programming, DP) — мощный метод решения сложных задач путём разбиения их на более простые подзадачи и **запоминания** уже решённых частей.
___
## Что такое динамическое программирование?

Динамическое программирование (Dynamic Programming, DP) — это метод проектирования алгоритмов, позволяющий решать сложные задачи путём их декомпозиции на более простые подзадачи и повторного использования уже вычисленных результатов. Несмотря на название, речь здесь идёт не о «программировании» в привычном смысле, а о **стратегии оптимизации вычислений**. Этот подход особенно полезен, когда задача обладает двумя ключевыми свойствами:

1. **Оптимальная подструктура** — оптимальное решение всей задачи может быть составлено из оптимальных решений её подзадач.
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи возникают многократно в процессе вычислений.

Если оба условия выполняются, динамическое программирование часто позволяет снизить вычислительную сложность с экспоненциальной до полиномиальной — что на практике означает переход от «нереализуемо долго» к «мгновенно».

> **Интересный факт**: термин «динамическое программирование» придумал математик Ричард Беллман в 1950-х. Он выбрал его, чтобы скрыть от военных, что занимается «математикой» — тогда слово «программирование» ассоциировалось с планированием, а «динамическое» звучало достаточно впечатляюще.

## Практическая ценность

Метод динамического программирования активно применяется в реальных инженерных и аналитических задачах:

- **Маршрутизация и навигация** — алгоритмы поиска кратчайшего пути (например, в GPS-сервисах) часто используют DP-подходы.
- **Обработка последовательностей** — сравнение геномов, выравнивание текстов, распознавание речи.
- **Финансовое планирование** — оптимизация портфелей, управление рисками, расчёт опционов.
- **Компиляторы и парсеры** — эффективный разбор грамматик и оптимизация кода.
- **Рекомендательные системы** — выбор оптимального набора элементов при ограничениях.

Понимание принципов DP помогает не только решать олимпиадные задачи, но и писать более эффективный, масштабируемый и предсказуемый код в повседневной разработке.


## Пример 1. Задача о размене денег (Coin Change)
 

> [!EXAMPLE] Постановка задачи
> Кассир должен выдать сдачу минимальным количеством монет.  
> Нужно посчитать, сколько монет потребуется для суммы `N`, если доступны номиналы `[1, 2, 5, 10]`.

### Сложность простого перебора

Если пытаться _перебрать напрямую все возможные комбинации монет_, чтобы составить сумму 23 из `[1, 2, 5, 10]`, — это означает:
- рассмотреть все наборы монет (в любом порядке),
- посчитать, какие из них дают сумму 23,
- выбрать тот, где монет меньше всего.

Пример:

`10 + 10 + 2 + 1 = 23  → 4 монеты 5 + 5 + 5 + 5 + 2 + 1 = 23 → 6 монет ...`

Таких комбинаций — **очень много**.  
На первый взгляд кажется, что 23 — маленькое число, но давайте оценим, **насколько растёт количество вариантов**.

Для каждой суммы мы можем:

- либо добавить монету 1,
- либо 2,
- либо 5,
- либо 10.

Если думать рекурсивно, для каждой промежуточной суммы мы можем разветвиться на 4 новых ветви.  
Это дерево решений растёт **экспоненциально**.

Оценка примерно:

`Количество_вариантов ~ 4^23 = 70,368,744,177,664 ≈ 70 триллионов`

Конечно, часть ветвей “умрёт” раньше (например, если сумма превысит 23),  но даже при этом количество комбинаций остаётся **огромным** — миллионы вариантов.

### Что делает динамическое программирование

Динамическое программирование позволяет **избежать повторного решения одинаковых подзадач**.

Например, при вычислении минимального количества монет для суммы 23 многократно требуется определить ответы для промежуточных сумм: 22, 21, 18 и других. В традиционном переборе каждая из этих подзадач решается заново, что приводит к экспоненциальному росту количества вычислений.

Промежуточные суммы нужны для того, чтобы **построить решение для большей суммы на основе уже известных оптимальных решений меньших сумм**.  
Для суммы 23 возможные варианты с использованием одной монеты:

- Взять монету 1 → остаётся сумма 22, общее количество монет = `dp[22] + 1`
- Взять монету 2 → остаётся сумма 21, общее количество монет = `dp[21] + 1`
- Взять монету 5 → остаётся сумма 18, общее количество монет = `dp[18] + 1`
- Взять монету 10 → остаётся сумма 13, общее количество монет = `dp[13] + 1`
    

Таким образом, для вычисления `dp[23]` достаточно использовать уже известные значения `dp[22]`, `dp[21]`, `dp[18]` и `dp[13]`. Это позволяет определить оптимальный размен без повторного перебора всех комбинаций.

#### Дерево вычислений (схема)

```
23 
├─ 22 (dp[22]) 
├─ 21 (dp[21]) 
├─ 18 (dp[18]) 
└─ 13 (dp[13])
```

Каждое значение `dp[i]` строится на основе меньших сумм. Использование этой схемы позволяет избежать многократного пересчёта одинаковых комбинаций.

Динамическое программирование сохраняет результаты этих подзадач в специальной структуре (массиве `dp`) и использует их повторно при необходимости. Таким образом достигается значительное снижение вычислительной сложности — с экспоненциальной до линейно-мультипликативной:

`O(Сумма × Количество_номиналов)`

В рассматриваемом примере это сокращает количество операций с триллионов до нескольких десятков.

#### Реализация на 1С: Элемент
```
метод Скрипт()
	// Доступные номиналы монет (массив номиналов)
    знч Номиналы = <Число>[1, 2, 5, 10]
    
    // Целевая сумма, которую нужно сложить из монет
    знч Сумма = 23
    
    // Массив dp: dp[i] будет хранить минимальное количество монет для суммы i
    знч dp = <Число>[]
    
    // Инициализируем массив dp нулями (в дальнейшем перезапишем)
    для i = 0 по Сумма
        dp.Добавить(0) // добавляем элемент в массив: dp[0], dp[1], ..., dp[Сумма]
    ;
    
    // Базовый случай: для суммы 0 нужно 0 монет
    dp[0] = 0 // 0 монет для суммы 0

    // Основной цикл: последовательно вычисляем dp[1], dp[2], ..., dp[Сумма]
    для i = 1 по Сумма
        // Инициализируем минимальное количество монет большим значением.
        // Сумма+1 — удобный "псевдо-бесконечный" предел:
        // нельзя набрать сумму i количеством монет больше, чем i (если есть монета 1).
        пер МинМонет = Сумма + 1

        // Перебираем все доступные номиналы монет
        для Ном из Номиналы
            // Если текущая монета не больше текущей суммы i,
            // то можно попытаться использовать эту монету
            если Ном <= i
                // dp[i - Ном] — минимальное число монет для оставшейся суммы
                // +1 — добавляем одну текущую монету
                // Берём минимум между текущим МинМонет и вариантом через эту монету
                МинМонет = Мин(МинМонет, dp[i - Ном] + 1)
            ;
        ;
        // Сохраняем лучший найденный вариант для суммы i
        dp[i] = МинМонет
    ;
    // Выводим ответ: минимальное количество монет для целевой суммы
    Консоль.Записать("Минимальное количество монет: " + dp[Сумма])
;
```


> [!NOTE] Вывод
> 
> Задача о размене денег (Coin Change) — не просто учебный пример динамического программирования, а универсальная модель оптимизации.
> 
> На практике принципы, заложенные в _Coin Change_, применяются в самых разных областях:
> 
> - Финансовые системы — подбор минимального количества купюр или монет при автоматическом расчёте сдачи, распределение платежей по доступным номиналам.
> - Логистика и упаковка — разбиение объёмов или веса на минимальное количество стандартных контейнеров.
> - Оптимизация вычислений — подбор комбинаций элементов с минимальной «стоимостью» (например, оптимизация памяти или времени выполнения).
> - Игровая механика и AI — нахождение наилучшей комбинации действий при ограниченных ресурсах.
> - Планирование и бюджетирование — составление оптимальных комбинаций затрат или задач для достижения заданной цели.
>     
> 
> Таким образом, _Coin Change_ — это не про монеты, а про **поиск наилучшего способа достичь цели при ограниченных ресурсах**.  
> Освоив этот алгоритм, разработчик получает универсальный инструмент мышления, применимый в любой задаче, где важно найти **оптимальную комбинацию из множества вариантов**.

## Пример 2: Наибольшая общая подпоследовательность (LCS)

Допустим, у вас есть две строки, например, `"ABCDGH"` и `"AEDFHR"`. Требуется найти **самую длинную подпоследовательность**, которая встречается в обеих строках в том же порядке (но не обязательно подряд). Это фундаментальная задача в биоинформатике (сравнение ДНК), системах контроля версий (например, `git diff`) и машинном обучении.

Это классическая задача динамического программирования, которая помогает выявлять **схожие части между двумя последовательностями**, сохраняя порядок элементов.

### Что такое подпоследовательность?

**Подпоследовательность** — это последовательность, которую можно получить из исходной, удалив некоторые элементы, не меняя порядок оставшихся.

**Пример:**  
Если дана строка `ABCBDAB`, то её подпоследовательностью может быть `ABD`, `ACB`, `ABAB` — но не `BAA` (так как нарушен порядок).

> [!EXAMPLE] Постановка задачи
> 
> Даны две последовательности (например, две строки):
> 
> - `X = "ABCBDAB"` 
> - `Y = "BDCAB"`
> 
> Нужно найти **наибольшую по длине последовательность**, которая является подпоследовательностью и `X`, и `Y`.
> 
> Результат:  
> `BCAB` или `BDAB` (длина 4).

### Реализация на 1С: Элемент

```
метод Скрипт()
    // Две входные строки, для которых ищем наибольшую общую подпоследовательность (LCS)
    знч Строка1 = "ABCBDAB"
    знч Строка2 = "BDCAB"

    // Вызываем метод, который вычислит саму подпоследовательность
    знч Результат = НайтиНаибольшуюОбщуюПодпоследовательность(Строка1, Строка2)

    // Вывод результата в консоль
    Консоль.Записать("Наибольшая общая подпоследовательность: %Результат")
;

@Локально
метод НайтиНаибольшуюОбщуюПодпоследовательность(Строка1: Строка, Строка2: Строка): Строка
    // Получаем длину каждой из строк
    знч Длина1 = Строка1.Длина()
    знч Длина2 = Строка2.Длина()

    // Создаём двумерный массив dp для хранения длин LCS для всех подстрок
    // dp[i][j] — длина наибольшей общей подпоследовательности для
    // первых i символов Строка1 и первых j символов Строка2
    знч dp = <Массив<Число>>[]
    для i = 0 по Длина1
        dp.Добавить(<Число>[])
        для j = 0 по Длина2
            dp[i].Добавить(0)  // Инициализируем все значения нулями
        ;
    ;

    // Заполняем таблицу dp по правилу динамического программирования:
    // если символы совпадают — добавляем 1 к предыдущему результату,
    // иначе — берём максимум из соседних значений
    для i = 1 по Длина1
        для j = 1 по Длина2

            // Извлекаем текущие символы строк
            // Метод Подстрока(От, До) возвращает символ от От до До (не включая До)
            знч Символ1 = Строка1.Подстрока(i - 1, i)
            знч Символ2 = Строка2.Подстрока(j - 1, j)

            если Символ1 == Символ2 
                // Символы совпали → увеличиваем длину LCS на 1 относительно диагонального элемента
                dp[i][j] = dp[i - 1][j - 1] + 1
            иначе
                // Символы не совпали → выбираем максимум из соседних (сверху или слева)
                dp[i][j] = Макс(dp[i - 1][j], dp[i][j - 1])
            ;
        ;
    ;

    // После заполнения таблицы dp[i][j] содержит длину LCS для всей пары строк
    // Теперь восстанавливаем саму подпоследовательность из таблицы

    пер i = Длина1
    пер j = Длина2
    пер Подпоследовательность = ""

    // Идём от конца таблицы к началу
    пока i > 0 и j > 0
        знч Символ1 = Строка1.Подстрока(i - 1, i)
        знч Символ2 = Строка2.Подстрока(j - 1, j)

        если Символ1 == Символ2 
            // Символы совпали — добавляем его в начало найденной подпоследовательности
            Подпоследовательность = Символ1 + Подпоследовательность

            // Смещаемся по диагонали (влево-вверх)
            i = i - 1
            j = j - 1
        иначе если dp[i - 1][j] >= dp[i][j - 1] 
            // Двигаемся вверх — в сторону большего значения
            i = i - 1
        иначе
            // Иначе двигаемся влево
            j = j - 1
        ;
    ;

    // Возвращаем собранную общую подпоследовательность
    возврат Подпоследовательность
;
```

Результат:
```
Наибольшая общая подпоследовательность: BCAB
```

### Общая идея алгоритма

1. Мы создаём таблицу `dp`, где `dp[i][j]` хранит **длину LCS** для первых `i` символов первой строки и первых `j` символов второй.
2. Заполняем таблицу по принципу:
    - если символы совпадают → увеличиваем предыдущую диагональ на 1;
    - если нет → берём максимум из значения **слева** и **сверху**.
3. После заполнения таблицы — восстанавливаем саму последовательность, двигаясь **обратно** (из нижнего правого угла к началу).

### Пример заполнения dp

Пошагово для строк `"ABCBDAB"` и `"BDCAB"`:

|||B|D|C|A|B|
|---|---|---|---|---|---|---|
||0|0|0|0|0|0|
|A|0|0|0|0|1|1|
|B|0|1|1|1|1|2|
|C|0|1|1|2|2|2|
|B|0|1|1|2|2|3|
|D|0|1|2|2|2|3|
|A|0|1|2|2|3|3|
|B|0|1|2|2|3|4|

Здесь каждая ячейка показывает длину LCS для соответствующих префиксов строк.  
В правом нижнем углу (dp[7][5] = 4) — длина наибольшей подпоследовательности.

### Восстановление результата

После того как таблица заполнена, алгоритм восстанавливает саму последовательность.  
Движение идёт **от конца к началу**:

`пока i > 0 и j > 0`

Проверяются те же символы:

- Если совпадают → добавляем символ **в начало результата** и сдвигаемся **по диагонали**.
    
- Если нет → двигаемся туда, где значение dp больше (вверх или влево).
    

Пошагово:

| i   | j   | Символ1 | Символ2 | Действие                    | Результат |
| --- | --- | ------- | ------- | --------------------------- | --------- |
| 7   | 5   | B       | B       | Совпали → добавить в начало | B         |
| 6   | 4   | A       | A       | Совпали → добавить          | AB        |
| 5   | 3   | D       | C       | Не совпали → вверх          | AB        |
| 4   | 3   | B       | C       | Не совпали → вверх          | AB        |
| 3   | 3   | C       | C       | Совпали → добавить          | CAB       |
| 2   | 2   | B       | D       | Не совпали → вверх          | CAB       |
| 2   | 1   | B       | B       | Совпали → добавить          | BCAB      |

### Сложность алгоритма

- **Время:** `O(n × m)`
- **Память:** `O(n × m)`  
    где `n` и `m` — длины входных строк.

Для длинных последовательностей применяются оптимизации — например, хранение только текущей и предыдущей строки `dp`.

### Практическое применение LCS
Задачи поиска наибольшей общей подпоследовательности используются гораздо шире, чем может показаться.

**Примеры:**

- Сравнение текстов — выявление отличий между версиями документов или исходных кодов (например, алгоритмы `diff`, `git`).
- Биоинформатика — сравнение генетических последовательностей (ДНК, белков).
- Поиск сходства данных — проверка совпадений в больших наборах строк или кодов.
- Автоматическое исправление ошибок — анализ различий между вводом пользователя и эталонной строкой (в системах автокоррекции).
- Обработка естественного языка (NLP) — сравнение предложений, оценка схожести смысловых структур.

> [!NOTE] Вывод
> Алгоритм **LCS** — это фундаментальная задача, которая демонстрирует силу динамического программирования: разложение сложной задачи на пересекающиеся подзадачи.
> На практике методы, основанные на LCS, лежат в основе множества современных технологий — от систем контроля версий до анализа генетических данных.
> Освоение этого алгоритма не только укрепляет понимание динамического программирования, но и развивает способность **мыслить оптимизационно**, находя решение там, где на первый взгляд кажется, что вариантов слишком много.

## Пример 3: Задача о рюкзаке (Knapsack Problem)

Предположим, имеется набор предметов, каждый из которых имеет **вес** и **ценность**.  
Нужно выбрать подмножество предметов, чтобы:

- суммарный вес не превышал заданной вместимости рюкзака;
- суммарная ценность была максимально возможной.

> [!NOTE] Постановка задачи
> 
> Турист собирается в поход и может взять с собой рюкзак ёмкостью **7 кг**.  
> Каждый предмет имеет **вес** и **ценность** — насколько он полезен в походе.
> 
> Доступны предметы:
> 
> 1. **Фонарь** — вес 1 кг, ценность 1
>     
> 2. **Аптечка** — вес 3 кг, ценность 4
>     
> 3. **Палатка** — вес 4 кг, ценность 5
>     
> 4. **Котелок** — вес 5 кг, ценность 7
>     
> 
> Как укомплектовать рюкзак так, чтобы общая **полезность** была максимальной,  но при этом не превысить допустимый вес?

#### Идея решения

Если рассматривать задачу перебором всех возможных комбинаций предметов, количество вариантов будет экспоненциальным — `2^n`.
Динамическое программирование позволяет **построить решение постепенно**, опираясь на результаты подзадач: 
- Для каждого предмета и каждой возможной вместимости рюкзака `w` определяем,  какую максимальную ценность можно получить,  если можно использовать предметы только до текущего индекса.

Эта зависимость формулируется так:
```
dp[i][w] = максимум(
    dp[i-1][w],                         // не берём предмет i
    dp[i-1][w - Вес[i]] + Ценность[i]   // берём предмет i, если помещается
)
```

### Реализация на 1С: Элемент

```
метод Скрипт()

    // Массив весов предметов
    знч Веса = <Число>[1, 3, 4, 5]

    // Массив ценностей предметов (соответствует массиву весов)
    знч Ценности = <Число>[1, 4, 5, 7]

    // Вместимость рюкзака
    знч Вместимость = 7

    // Количество предметов
    знч N = Веса.Размер()

    // Создаём двумерный массив dp:
    // dp[i][w] = максимальная ценность для первых i предметов и вместимости w
    знч dp = <Массив<Число>>[]
    для i = 0 по N
        знч Строка = <Число>[]
        для w = 0 по Вместимость
            Строка.Добавить(0)
        ;
        dp.Добавить(Строка)
    ;

    // Основной цикл динамического программирования
    для i = 1 по N
        для w = 1 по Вместимость
            // Текущий предмет имеет вес и ценность:
            знч Вес = Веса[i - 1]
            знч Цена = Ценности[i - 1]

            // Если предмет помещается в текущий рюкзак
            если Вес <= w 
                // Выбираем максимум между:
                // 1) не брать предмет (dp[i-1][w])
                // 2) взять предмет (dp[i-1][w - Вес] + Цена)
                dp[i][w] = Макс(dp[i - 1][w], dp[i - 1][w - Вес] + Цена)
            иначе
                // Если не помещается — просто копируем значение без этого предмета
                dp[i][w] = dp[i - 1][w]
            ;
        ;
    ;

    // Максимальная ценность хранится в dp[N][Вместимость]
    Консоль.Записать("Максимальная ценность: " + dp[N][Вместимость])
;
```

Результат
```
Максимальная ценность: 9
```

#### Как работает алгоритм

1. **Инициализация:**  
    Первая строка и первый столбец матрицы `dp` равны 0 — это означает, что без предметов или при нулевой вместимости ценность всегда 0.
2. **Построение таблицы:**  
    Для каждого предмета и каждой возможной вместимости `w` рассматриваются два варианта:
    - Не включать предмет.
    - Включить предмет (если помещается) и прибавить его ценность к лучшему результату для оставшегося места `w - Вес`.        
3. **Результат:**  
    Последняя ячейка `dp[N][Вместимость]` содержит максимальную суммарную ценность, достижимую при данных ограничениях.

#### Визуализация таблицы `dp`
Каждая **строка** соответствует тому, сколько предметов мы **уже рассматриваем** (от 0 до 4).  
Каждая **колонка** отражает возможную **вместимость рюкзака** — от 0 до 7 кг.

В ячейке `dp[i][w]` хранится:
> максимальная ценность, которую можно получить,  
> используя **первые `i` предметов** при рюкзаке вместимости `w`.

| i / w             | 0   | 1   | 2   | 3   | 4   | 5   | 6   | 7   |
| ----------------- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 (без предметов) | 0   | 0   | 0   | 0   | 0   | 0   | 0   | 0   |
| 1 (**Фонарь**)    | 0   | 1   | 1   | 1   | 1   | 1   | 1   | 1   |
| 2 (**Аптечка**)   | 0   | 1   | 1   | 4   | 5   | 5   | 5   | 5   |
| 3 (**Палатка**)   | 0   | 1   | 1   | 4   | 5   | 6   | 6   | 9   |
| 4 (**Котелок**)   | 0   | 1   | 1   | 4   | 5   | 7   | 8   | 9   |

#### Как читать таблицу

1. **Первая строка (0 предметов)**  
    Всё очевидно: если предметов нет — ценность равна 0 при любой вместимости.
2. **Вторая строка (Фонарь, вес 1, ценность 1)**  
    Теперь можно взять только фонарь.  
    При любой вместимости ≥ 1 ценность становится 1, ведь фонарь помещается.
3. **Третья строка (добавляется Аптечка, вес 3, ценность 4)**
    - Для `w < 3` аптечка не помещается, поэтому значения совпадают с предыдущей строкой.
    - При `w = 3` выгоднее взять аптечку (ценность 4), чем фонарь (1).
    - При `w = 4` можно взять аптечку (4) и фонарь (1) = **5** — и это видно в таблице.
4. **Четвёртая строка (добавляется Палатка, вес 4, ценность 5)**
    - Для `w < 4` палатка не помещается, поэтому остаются прежние значения.
    - При `w = 5` можно выбрать между «аптечка + фонарь» (5) и «палатка» (5) — результат одинаков.
    - При `w = 7` можно взять аптечку (3 кг, 4) + палатку (4 кг, 5) = **9** — это максимальная ценность.
5. **Пятая строка (добавляется Котелок, вес 5, ценность 7)**
    - При `w = 5` выгодно взять котелок (7) — это лучше аптечки + фонаря (5).
    - При `w = 6` можно добавить фонарь к котелку (8).
    - Но при `w = 7` комбинация аптечки и палатки (9) остаётся оптимальной.
#### Что показывает таблица

- Каждая новая строка — шаг размышления:  
    «А что, если добавить ещё один предмет в набор?»
    
- В каждой ячейке сравниваются два варианта:
    
    1. **Не брать** текущий предмет → остаётся `dp[i-1][w]`.
    2. **Взять** текущий предмет → добавляется его ценность к `dp[i-1][w - Вес]`.

Алгоритм выбирает **максимум** из этих двух вариантов — и так шаг за шагом формирует оптимальное решение.

#### Интерпретация результата

Последняя ячейка `dp[4][7] = 9` показывает,  
что максимальная ценность при вместимости **7 кг** равна **9**.
Это достигается, если взять:

- **Аптечку** (3 кг, 4)
- **Палатку** (4 кг, 5)

**Итог:**  
Максимальная ценность при вместимости 7 — **9**  
(например, можно взять предметы весом 3 кг и 4 кг).

#### Практическая значимость

Динамическое программирование в форме задачи о рюкзаке лежит в основе множества реальных решений:

- **Оптимизация бюджета:** выбор проектов или инвестиций с максимальной отдачей при ограниченном финансировании.
- **Планирование ресурсов:** распределение времени, вычислительных мощностей или складских запасов.
- **Логистика и доставка:** подбор грузов под ограничение вместимости транспорта.
- **IT и DevOps:** оптимизация размещения задач по вычислительным узлам или выбор параметров кэширования.
- **Финансовые приложения:** подбор портфеля активов под заданный риск и доходность

> Она демонстрирует, как пошаговое построение решений и использование ранее найденных результатов позволяет эффективно решать задачи, где **прямой перебор невозможен из-за комбинаторного взрыва**.
> 
> Ключевые выводы:
> 
> 1. **Оптимизация выбора.**  
>     Алгоритм наглядно показывает, как можно принимать рациональные решения при ограниченных ресурсах — например, когда необходимо выбрать подмножество элементов с максимальной ценностью при заданном лимите.
> 2. **Переиспользование вычислений.**  
>     Вместо пересчёта одинаковых комбинаций множество раз, алгоритм сохраняет результаты подзадач, что снижает вычислительную сложность с экспоненциальной до квазилинейной `O(N × C)`. 
> 3. **Модульность и универсальность.**  
>     Подход, использованный в задаче о рюкзаке, универсален. Его можно адаптировать к широкому спектру прикладных задач — от управления проектами до анализа данных.

## Заключение

Динамическое программирование — это не просто алгоритмический приём, а **подход к мышлению**, позволяющий решать сложные задачи шаг за шагом, опираясь на результаты уже решённых подзадач.

Рассмотренные примеры — **размен денег**, **наибольшая общая подпоследовательность** и **задача о рюкзаке** — демонстрируют ключевые принципы DP:

1. **Разбиение задачи на подзадачи.**  
    Каждая большая задача декомпозируется на более простые элементы. Например, для суммы 23 важны результаты для сумм 22, 21 и 18; для LCS — длины подпоследовательностей меньших префиксов; для рюкзака — максимальная ценность для меньших комбинаций предметов и вместимостей.
2. **Повторное использование вычислений.**  
    Вместо пересчёта одних и тех же вариантов множество раз, алгоритм хранит промежуточные результаты в структурах `dp`. Это позволяет снизить вычислительную сложность с экспоненциальной до полиномиальной.
3. **Оптимальность решений.**  
    DP гарантирует, что финальный результат строится из **оптимальных решений подзадач** — минимальное количество монет, максимальная ценность рюкзака или самая длинная общая подпоследовательность.
4. **Универсальность подхода.**  
    Несмотря на разную природу задач, принцип один: сохранение промежуточных результатов и последовательное их использование. Именно поэтому динамическое программирование широко применяется в маршрутизации, финансовом планировании, биоинформатике, обработке текста и многих других областях.

Освоение динамического программирования — это не только приобретение конкретных алгоритмов, но и развитие системного мышления: способность видеть **структуру задачи**, распознавать повторяющиеся элементы и эффективно использовать их.  В итоге даже задачи с миллионами комбинаций становятся решаемыми, а решения — предсказуемыми и оптимальными.
